# 联网竞拍游戏：可验证首个垂直切片

Status: ready-for-agent

## Problem Statement

需要在 Unity 模板中实现一个可用于求职展示的 2D 联网竞拍游戏。四个可配置的玩家席位围绕同一个隐藏包裹连续竞拍；玩家必须根据公共与私有线索估计包裹总价值，并在服务器权威裁定下完成出价、获胜与资产结算。

该项目还需要证明三种能力可以共存：Photon Fusion 专用服务端联网、可被真人或 AI 互换控制的玩家席位，以及不依赖 Unity UI 或网络运行时即可验证的规则核心。

## Solution

实现一个以服务端权威对局核心为唯一高层缝的首个垂直切片。该核心接收时间推进、连接状态与统一席位动作，产生经信息权限过滤的席位视角、回合揭示与结算结果。Fusion 专用服务端负责承载该核心并同步状态；客户端只显示自身视角并提交动作；AI 只从所属席位视角决策并通过同一动作入口提交。

本切片涵盖可生成且可结算的动态包裹、线索、连续竞拍、断线 AI 接管、运行内资产与基础 2D 展示。所有可调数值和内容数据从配置读取，不将当前四人、轮次倍率或经济参数硬编码为业务规则。

## User Stories

1. 作为玩家，我想加入一个可配置席位数的对局，以便与真人和 AI 一同竞拍。
2. 作为玩家，我想在启动对局时看到自己的运行内资产，以便知道最高可出价金额。
3. 作为玩家，我想在同一次连接的连续对局间保留资产，以便获得局外积累体验。
4. 作为重新连接的玩家，我想以新的固定初始资产加入后续可用对局，以便不受旧连接或旧对局影响。
5. 作为在对局开始后才连接的玩家，我想被安排等待下一局，以便不改变进行中的席位归属。
6. 作为玩家，我想在默认画面只看到固定宽度的包裹网格，以便通过线索进行推理而非直接看到真值。
7. 作为玩家，我想查阅公开藏品目录的名称、外观、尺寸、珍稀度和具体价值，以便理解可出现的内容。
8. 作为玩家，我想知道包裹中的藏品可以重复出现，以便正确评估线索所代表的总价值。
9. 作为玩家，我想看到每轮开始时的公共线索，以便获得所有席位共享的信息。
10. 作为玩家，我想从本轮共享候选线索集中选择一条私有线索，以便形成自己的判断。
11. 作为玩家，我想在提交私有线索选择后立即看到仅属于我的结果，以便在出价前分析。
12. 作为玩家，我想在分析阶段看不到其他玩家的私有线索结果，以便保留不完全信息博弈。
13. 作为玩家，我想在出价阶段看不到其他玩家的出价和选择，以便每次出价都是封闭提交。
14. 作为玩家，我想在回合揭示时看到所有席位的出价、所选线索类型和本轮结果，以便理解竞拍进展。
15. 作为玩家，我想在分析阶段倒计时结束后失去本轮私有线索，而不是由系统替我选择，以便超时惩罚明确。
16. 作为玩家，我想在出价阶段倒计时结束后以零元放弃竞拍，以便对局不会无限等待。
17. 作为玩家，我想只能提交不高于可用资产的整数出价，以便不能透支或利用小数精度。
18. 作为玩家，我想将零元明确视为放弃竞拍，以便第五轮后不会出现零元成交。
19. 作为玩家，我想在只有一人有效出价时直接成交，以便不必等待倍率降至一。
20. 作为玩家，我想在有多个有效出价时按当前轮获胜倍数判定成交，以便高价必须拥有相应优势。
21. 作为玩家，我想在同价最高时由服务端先认可的出价获胜，以便不依赖本地时钟或客户端网络判断。
22. 作为玩家，我想在未成交轮不发生资产变化并进入下一轮，以便试探性出价没有额外成本。
23. 作为玩家，我想在第五轮及之后由倍率为一的最高有效出价成交，以便对局最终趋向结束。
24. 作为玩家，我想在第五轮之后全员弃拍时继续下一轮，直到达到可配置连续弃拍上限，以便零元不被当作成交。
25. 作为玩家，我想在达到连续弃拍上限时以未成交结束且资产不变，以便对局有清晰的无成交出口。
26. 作为赢家，我想在包裹总价值高于出价时自动获得 `Y - Xw` 资产，以便不必手动处理藏品结算。
27. 作为赢家，我想在出价高于包裹总价值时承担对应损失，以便错误估值具有经济后果。
28. 作为非赢家席位，我想在赢家损失时按配置比例获得整数亏损分配，以便经济规则对所有席位一致。
29. 作为玩家，我想在结算时可查看包裹的完整组成与价值，但不让展示影响已完成的经济结算。
30. 作为玩家，我想在本局持续保留已经通过公共或私有线索得知的信息，以便跨轮推理。
31. 作为玩家，我想通过珍稀度形状线索看到目标珍稀度藏品的边界、形状和珍稀度，而不直接获知身份或价值，以便获取部分信息。
32. 作为玩家，我想通过随机完整揭示线索看到一件藏品实例的完整信息，以便基于精确信息估值。
33. 作为玩家，我想允许公共线索和私有线索内容重叠、并允许线索跨轮重复，以便线索抽取保持简单且可扩展。
34. 作为玩家，我想让本轮候选线索集内部互不重复、但所有玩家可选择同一条，以便选择公平且没有抢占。
35. 作为仍在线的玩家，我想在他人断线后由 AI 接管其旧席位，以便本局能继续完成。
36. 作为断线玩家，我想知道自己的旧对局资产和收益不再关联新连接，以便当前阶段的身份语义明确。
37. 作为玩家，我想让 AI 的决策仅基于它所在席位可见的公共和私有信息，以便 AI 不利用服务端真值。
38. 作为玩家，我想让 AI 的提交带有随机延迟且不会比最后一个真人提交晚超过一秒，以便其时序表现自然且不拖慢回合。
39. 作为内容设计者，我想从预定义藏品目录构建动态包裹，并对包裹总价值和各珍稀度价值施加配置约束，以便控制对局数值范围。
40. 作为内容设计者，我想随机摆放矩形藏品且保证非重叠、列方向无空洞、没有按珍稀度排序的规律，以便网格本身不泄露价值。
41. 作为开发者，我想让真人、当前规则 AI、未来行为树 AI 和未来状态机 AI 使用相同席位动作接口，以便替换控制者不影响规则系统。
42. 作为开发者，我想将 Photon Fusion 专用服务端设为唯一竞拍权威，以便客户端不裁定包裹、计时、顺序或资产。
43. 作为开发者，我想不依赖 Unity 场景、UI 或网络运行时测试完整对局规则，以便快速验证边界情形并防止联网实现漂移。

## Implementation Decisions

- 新建服务端权威对局核心，作为唯一高层业务缝。它拥有对局状态、包裹真值、阶段倒计时、有效出价顺序、结算和可见性过滤。
- 核心接受统一的席位动作：选择私有线索、提交出价；真人和 AI 不获得独立规则入口。
- 核心接受可控的时间推进与随机源，从而使倒计时、AI 延迟、包裹生成和线索抽取可复现并可测试。
- 核心分别生成权威完整状态和按席位过滤的席位视角。客户端与 AI 只能消费席位视角；完整状态不得经同步数据暴露给客户端。
- Fusion 使用本地专用服务端模式。服务端拥有 State Authority；客户端发送动作请求并接收过滤后的同步状态或事件。
- 席位数 `P`、候选线索数 `n`、分析和出价时长、前四轮获胜倍数、第五轮后的倍率、连续弃拍上限、初始资产、亏损分配比例、网格宽度和包裹生成约束均为规则配置。
- 货币使用整数最小货币单位。出价必须为非负整数且不高于该玩家可用资产；仅大于零者是有效出价。
- 多个有效出价的排序为金额降序、权威接受顺序升序；第二高出价是排序第二名。最高有效出价满足 `最高有效出价 >= 获胜倍数 × 第二高有效出价` 时成交。
- 仅一个有效出价时第二高出价按零处理并直接成交；无有效出价不会成交。第五轮及之后全员弃拍会继续，直到连续弃拍上限触发未成交结束。
- 成交时，赢家资产变化为 `Y - Xw`。若 `Y < Xw`，每个非赢家席位获得向下取整的 `r × (Xw - Y) ÷ (P - 1)`；余数离开本局经济系统。未成交轮和未成交结束不改变资产。
- 对局开始用 AI 填补空席位；断线席位由 AI 接管直至旧对局结束。旧人类控制者立刻失去该局收益关联；AI 自身资产结算弃置，但其席位仍参与亏损分配的接收范围。
- 运行内资产与客户端连接身份关联：连接时分配固定初始资产，同次连接可跨局累积；重连创建新身份与初始资产。
- 首版仅实现一种简单规则 AI；其逻辑位于控制者适配层，不作为服务端配置，也不读取真值。
- 包裹内容来自预定义藏品目录，允许同目录项重复抽取；生成器必须满足包裹总价值与各珍稀度价值的配置约束。布局由独立生成器产生，保证矩形不重叠和列方向无空洞。
- 线索系统区分公共线索、候选线索集和私有结果。候选线索集在单轮无放回抽取；未来轮次允许重复；公共与私有线索允许重叠。
- 2D UI 只承担默认网格、线索结果、倒计时、提交操作、回合揭示和基础结算展示；不包含规则裁定。
- 相关既有决定遵循 `docs/adr/0001-authoritative-bid-ordering.md` 至 `docs/adr/0005-ai-limited-to-player-slot-knowledge.md`。

## Testing Decisions

- 高层测试只通过服务端权威对局核心的外部输入和外部输出验证行为，不断言内部字段、类结构或 Fusion 回调细节。
- 测试使用受控时间与确定性随机源，覆盖阶段切换、超时、AI 延迟上限、包裹与线索生成，以及同价顺序。
- 核心测试覆盖：金额与资产校验、零元放弃、单人有效竞价、倍率成交、同价名次、未成交轮、第五轮后的连续弃拍上限、赢家利润、赢家亏损和整数余数。
- 核心测试覆盖：私有结果仅对所属席位可见、提交后立即可见、出价阶段前不泄露他人出价、回合揭示时统一公开选择类型和出价，以及 AI 不可读取真值或其他席位私有信息。
- 核心测试覆盖：空席位 AI 补位、真人断线后的 AI 接管、断线玩家不收取旧局收益、AI 接管席位仍在亏损分配接收范围、重连创建新身份。
- 包裹与布局测试验证配置约束、重复抽取许可、矩形非重叠、列方向无空洞、固定宽度与自动高度；不依赖某次随机布局的具体位置。
- Fusion 集成测试只验证客户端不能取得权威真值、服务端能认可合法动作并同步席位视角；规则边界仍由对局核心测试覆盖。
- UI 验证只覆盖用户能够看到和提交的基本流程，不复制业务规则断言。
- 当前仓库没有可复用的业务测试先例；首批测试将为该 Unity 项目建立对局核心的行为测试基线。

## Out of Scope

- 长期账号、持久化资产、认证、断线重连恢复旧身份或旧对局控制权。
- 匹配系统、房间列表、云部署、反作弊、生产级服务端运维与真实外网发布。
- 多种 AI 的效果比较、行为树和状态机 AI 的完整实现；首版只需一种简单规则 AI。
- 高完成度的结算演出、完整美术、音效、可访问性、本地化与商业化系统。
- 藏品目录的大规模正式内容生产与数值平衡，只提供能验证约束与线索的最小内容集。
- 对局中交易包裹内单个藏品、玩家库存或逐藏品经济结算。

## Further Notes

- 本 PRD 只固定已确认的语义；未确定的具体数值保持为规则或内容配置，不自行补定默认值。
- 开发应优先完成可验证的服务端权威对局核心，再让 Fusion、AI 与 2D UI 各自连接到该核心。
- 后续任务应以垂直切片交付，避免先铺设大量网络或 UI 框架而没有可完成的对局。
